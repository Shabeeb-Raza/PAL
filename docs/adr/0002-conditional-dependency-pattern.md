# Conditional Dependency Pattern for Policy Rules

IOBM's academic policies include conditional dependencies where outcome B depends on condition A being met first (e.g., "must pass theory before lab"). Rather than hardcoding each policy, the rule engine represents these as a reusable pattern: a policy has a condition (student data check), a trigger (when the condition fails), and an outcome (what happens to dependent entities). For the MVP, the rule engine handles the core policies: prerequisite eligibility, CGPA thresholds, credit-hour limits, core course completion, and the theory-before-lab conditional dependency. Complex edge-case policies (attendance-based exam eligibility, maximum attempt limits) are deferred to Phase 2. Each policy evaluation produces an auditable result: the policy name, the data values checked, and whether the outcome was pass, fail, or warning.
